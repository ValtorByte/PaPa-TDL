# راهنمای PaPa-TDL

فایل‌های تلگرام را روی **گوگل‌درایو** یا **پوشهٔ دلخواه سرور** ذخیره کنید. مقصد پیش‌فرض گوگل‌درایو است. ورود تلگرام با شماره، کد و در صورت نیاز رمز دومرحله‌ای انجام می‌شود؛ دوربین یا API ID/hash شخصی تلگرام لازم نیست.

[English](README.md) · [راهنمای فرمان‌ها](#فرمانهای-روزمره)

## نصب

نصب‌کنندهٔ تک‌دستوری برای Ubuntu 24.04 به بالا و Debian 12 به بالا آماده شده است. خود برنامه با Python 3.11+ و Chromium روی Linux، macOS و Windows هم اجرا می‌شود؛ راهنمای نصب دستی هر سیستم در [README انگلیسی](README.md#install) آمده است. برای مرورگر و فایل‌ها فضای کافی لازم است.

```bash
sudo bash -c "$(curl --proto '=https' --tlsv1.2 -fsSL https://raw.githubusercontent.com/ValtorByte/PaPa-TDL/main/install.sh)" @ install
```

برای نصب از پوشه‌ای که کد جدید داخلش است:

```bash
sudo bash install.sh install
```

سپس برنامه را باز کنید:

```bash
papa-tdl
```

نصب‌کننده محیط خصوصی Python را با `--without-pip` می‌سازد و pip را جداگانه اضافه می‌کند؛ مرحلهٔ مشکل‌دار `ensurepip` اجرا نمی‌شود. اگر نصب قبلی وسط کار متوقف شده باشد، طبیعی است که هنوز `papa-tdl` وجود نداشته باشد. ابتدا نصب نسخهٔ جدید را کامل کنید.

Docker و systemd برای نصب بومی لازم نیستند. برنامه با حساب غیرروت اجرا می‌شود. نام حساب اجرایی و مسیر دقیق داده‌های خصوصی در پایان نصب چاپ می‌شود؛ این اطلاعات را نگه دارید.

## اجرای اول

اجرای اول `papa-tdl` راه‌اندازی اولیه را باز می‌کند. برای قبول هر پیش‌فرض Enter بزنید:

| تنظیم | پیش‌فرض |
| --- | --- |
| مقصد | Google Drive |
| پوشهٔ Drive | `TDL`؛ بعد از ورود گوگل خودکار آماده می‌شود |
| گروه تلگرام | `TDL` |
| پوشهٔ ذخیره روی سرور | `DATA_DIR/downloads`؛ خودکار ساخته می‌شود |
| فایل‌های در حال انتقال | `DATA_DIR/pending` |

۱. مقصد `drive` یا `local` را انتخاب کنید. اگر مسیر/پوشه‌ای انتخاب نکنید، پیش‌فرض استفاده می‌شود.

۲. برای Drive، ورود معمولی گوگل در مرورگر را انجام دهید. نسخه‌ای که هویت OAuth برنامه در آن تنظیم شده باشد، فایل JSON از کاربران نمی‌خواهد. برنامه بدون رضایت شما به حساب گوگل متصل نمی‌شود و مقصد را مخفیانه عوض نمی‌کند.

۳. ورود تلگرام را انجام دهید: شماره را با کد کشور، مثلاً `+989123456789`، وارد کنید. شمارهٔ موبایل ایرانی با `09` هم پذیرفته می‌شود. **شماره هنگام تایپ دیده می‌شود؛ فقط کد و رمز دومرحله‌ای مخفی‌اند.**

۴. گروه `TDL` را در تلگرام بسازید یا از گروه موجود استفاده کنید و یک فایل کوچک داخلش بفرستید.

۵. در منو **Check destination** و سپس **Start background watcher** را انتخاب کنید. در **View logs** نتیجهٔ ذخیره را ببینید و مقصد را بررسی کنید.

منو اتصال‌هایی را که اخیراً واقعاً بررسی شده‌اند با تیک سبز نشان می‌دهد؛ نشست ذخیره‌شده‌ای که هنوز بررسی نشده، «تأییدنشده» است. نشست معتبر در اجراهای بعدی دوباره استفاده می‌شود.

## اتصال گوگل‌درایو

اگر مقصد `local` است، این بخش را لازم ندارید.

با `papa-tdl drive-login` لینک HTTPS بگیرید و آن را روی کامپیوتر یا گوشی باز کنید. بعد از تأیید گوگل، مرورگر موفقیت را نشان می‌دهد و VPS اتصال را خودکار کامل می‌کند. تا نمایش `Google Drive connected` دستور را باز نگه دارید. کاربران نیازی به JSON، Client ID، کپی کد یا تونل SSH ندارند. پیش از انتشار این نسخه، مدیر پروژه باید [سرویس ورود مرکزی](ops/HOSTED-OAUTH.md) را فعال کند.

سرویس مرکزی هنگام اتصال توکن‌ها را موقتاً پردازش می‌کند و درخواست تمدید را به گوگل می‌فرستد. فایل‌های تلگرام از این سرویس عبور نمی‌کنند. جزئیات در [سیاست حریم خصوصی](https://valtorbyte.ir/papa-tdl/privacy/) آمده است. راهنمای Desktop زیر فقط روش شخصی و اختیاری است.

مراحل زیر فقط برای استفاده از OAuth Client شخصی اختیاری است:

۱. در [Google Cloud Console](https://console.cloud.google.com/) یک پروژه بسازید و **Google Drive API** را فعال کنید.

۲. صفحهٔ رضایت OAuth را تنظیم کنید. اگر در حالت **Testing** است، حساب گوگل خود را به test users اضافه کنید.

۳. یک OAuth Client از نوع **Desktop app** بسازید و فایل JSON آن را دانلود کنید. این فایل مشخصات برنامه برای گوگل است و رمز حساب گوگل شما نیست.

فایل JSON را در `DATA_DIR/google-client.json` بگذارید؛ مسیر `DATA_DIR` را با `papa-tdl status` ببینید. فایل فقط باید برای حساب اجرایی برنامه خواندنی باشد. برای تنظیم شخصی می‌توانید با `--client-file` مسیر آن را بدهید؛ در اجرای عادی دیگر مسیر JSON پرسیده نمی‌شود. فایل زیر `/root` معمولاً برای برنامهٔ غیرروت خواندنی نیست. JSON و توکن‌ها را در گیت‌هاب نگذارید.

اگر برنامه روی **VPS** است، روی **کامپیوتر خودتان** یک ترمینال دوم باز کنید و این اتصال SSH را تا پایان ورود باز نگه دارید:

```bash
ssh -N -L 53682:127.0.0.1:53682 YOUR_SSH_USER@YOUR_VPS
```

روی **VPS** اجرا کنید:

```bash
papa-tdl drive-login --method browser
```

لینک ورود گوگل را که در ترمینال چاپ می‌شود، در مرورگر کامپیوتر باز کنید و دسترسی را تأیید کنید. پاسخ مرورگر از تونل SSH به برنامهٔ VPS می‌رسد. وقتی پوشهٔ Drive هم بررسی شد، ترمینال VPS پیام `Google Drive connected` را نشان می‌دهد. **در این روش کد TV وارد نمی‌کنید.** اگر برنامه و مرورگر روی یک کامپیوترند، تونل SSH لازم نیست.

اگر فایل JSON جای دیگری است، مسیر خواندنی آن را بدهید:

```bash
papa-tdl drive-login --method browser --client-file /absolute/path/to/desktop-client.json
```

روش قدیمی `--method device` به کلاینت TV شخصی و اسکوپ‌های مجاز گوگل نیاز دارد و روش پیشنهادی Drive نیست. ورود پیش‌فرض از کلاینت Web مدیر پروژه استفاده می‌کند و سکرت آن فقط روی سرور مرکزی می‌ماند.

حالا:

```bash
papa-tdl check
papa-tdl login
papa-tdl start
papa-tdl logs -f
```

پوشهٔ `TDL` خودکار ایجاد یا دوباره استفاده می‌شود؛ وارد کردن شناسهٔ پوشه اجباری نیست. دسترسی محدود `drive.file` استفاده می‌شود و به معنی دسترسی به تمام پوشه‌های قدیمی نیست. فایل‌ها خصوصی می‌مانند. توکن تا وقتی گوگل اجازه دهد تازه می‌شود؛ لغو دسترسی یا انقضای مجوز حالت Testing به ورود مجدد نیاز دارد.

منوی ترمینال هنگام تغییر عرض دوباره رسم می‌شود. زیر ۱۰۰ ستون به فهرست جمع‌وجور و زیر ۵۵ ستون به عنوان ساده تبدیل می‌شود. پس از ارتقا، اجرای دوبارهٔ `papa-tdl` نمای قدیمی را جایگزین می‌کند.

## ذخیره روی سرور

در `papa-tdl setup` گزینهٔ `local` را انتخاب کنید. برای پوشهٔ آمادهٔ پیش‌فرض Enter بزنید یا مسیر کامل و قابل نوشتن بدهید. ورود گوگل لازم نیست.

```bash
papa-tdl setup
papa-tdl login
papa-tdl check
papa-tdl start
```

برای تغییر مسیر فقط در یک اجرا:

```bash
papa-tdl start --output /home/YOUR_USER/telegram-files
```

برای مسیری مانند `/srv/tdl`، مدیر سرور ابتدا آن را به حساب اجرایی برنامه اختصاص دهد:

```bash
sudo install -d -m 700 -o RUNTIME_USER /srv/tdl
papa-tdl start --output /srv/tdl
```

## فرمان‌های روزمره

### استخراج فایل‌های چندپارتی

فایل‌های ZIP، RAR یا 7z را در گروه خصوصی تنظیم‌شده ارسال کنید. فایل‌هایی با نام‌هایی مثل `.part1.rar`، `.part2.rar`، `.7z.001` و `.zip.001` خودکار کنار هم قرار می‌گیرند. آرشیوهای مستقل شماره‌دار مثل `Course_Part01 (01-22).rar` و `Course_Part02 (23-43).rar` هم در یک پوشه پردازش می‌شوند و محتوای هرکدام در زیرپوشهٔ `Part01`، `Part02` و مانند آن قرار می‌گیرد تا فایل‌های هم‌نام مثل `photo.jpg` حذف یا جایگزین نشوند. آرشیوهای داخل یک آلبوم تلگرام هم یکجا پردازش می‌شوند. برنامه ۳۰ ثانیه بعد از آخرین پارت شروع به استخراج می‌کند و نتیجه را در یک پوشه داخل `TDL` ذخیره می‌کند. آرشیوهای تکی هم خودکار استخراج می‌شوند.

روش دستی همچنان در دسترس است: `/extract`، سپس فایل‌ها، سپس `/done`. اگر پارتی کم باشد یا استخراج خطا بدهد، فایل‌ها در فضای بازیابی خصوصی می‌مانند. گزینهٔ ۱ منو، **Live service** را باز می‌کند؛ دستور `papa-tdl console` هم همین نما را باز می‌کند. رمز آرشیو همان‌جا با ورودی مخفی پرسیده می‌شود و رمز اشتباه را می‌توان دوباره وارد کرد. خطاها در ترمینال نمایش داده می‌شوند و در گروه تلگرام ارسال نمی‌شوند. Ctrl+C مستقیم به منو برمی‌گردد و سرویس پس‌زمینه فعال می‌ماند. دستور جداگانهٔ `extract-password` اختیاری است؛ رمز را از راه یک سوکت خصوصی محلی به watcher می‌رساند و روی دیسک ذخیره نمی‌کند. یک آرشیو منتظر رمز یا پارت، پردازش فایل‌های مستقل را متوقف نمی‌کند.

اندازهٔ نمایش‌داده‌شده در Telegram Web تقریبی است؛ برنامه پس از پایان دانلود، تعداد دقیق بایت‌های فایل را برای بررسی بعد از ری‌استارت ثبت می‌کند. اگر خود آرشیو ناقص باشد، باید نسخهٔ کامل پارت آسیب‌دیده را دوباره تهیه کنید.

نصب‌کنندهٔ Ubuntu/Debian ابزار 7-Zip و در صورت دسترسی بستهٔ پشتیبانی RAR را نصب می‌کند. نصب دستی برای RAR به `unrar` یا 7-Zip دارای پشتیبانی RAR و برای 7z و فایل‌های split به `7zz`، `7z` یا `7za` نیاز دارد.

| فرمان | کاربرد |
| --- | --- |
| `papa-tdl` | باز کردن منو |
| `papa-tdl setup` | تغییر مقصد، گروه یا مسیر ذخیره |
| `papa-tdl login` | ورود تلگرام |
| `papa-tdl drive-login` | ورود معمولی گوگل در مرورگر و تشخیص خودکار تأیید |
| `papa-tdl check` | بررسی مقصد و آماده کردن پوشه |
| `papa-tdl start` | شروع watcher در پس‌زمینه |
| `papa-tdl console` | نمایش زندهٔ سرویس، خطاها و درخواست خودکار رمز در همان صفحه |
| `papa-tdl extract-password` | واردکردن مخفی رمز آرشیو در ترمینال، وقتی watcher منتظر رمز است |
| `papa-tdl status` | وضعیت watcher و مسیر داده‌های خصوصی |
| `papa-tdl logs -f` | مشاهدهٔ پیشرفت؛ Ctrl+C فقط نمایش لاگ را می‌بندد |
| `papa-tdl stop` | توقف با حفظ نشست و فایل‌ها |
| `papa-tdl retry` | تلاش مجدد برای فایل‌های کامل معلق |
| `papa-tdl telegram --ids 55,56 --once` | ذخیرهٔ پیام‌های انتخابی که در مرورگر دیده می‌شوند |

برای تغییر یک‌بارهٔ مقصد از `--to drive` یا `--to local` استفاده کنید. گزینهٔ `--output` مقصد محلی را انتخاب می‌کند. قبل از تغییر تنظیمات، ورود مجدد یا آپدیت، watcher را متوقف کنید.

با قطع SSH اجرا ادامه دارد؛ **بعد از ریبوت باید دوباره `papa-tdl start` اجرا شود** یا اجرای آن را در مدیر پردازش میزبان تنظیم کنید.

## خطاها و محدودیت‌ها

- **ensurepip شکست خورد:** نصب‌کنندهٔ ۱٫۱ یا جدیدتر را استفاده کنید؛ روش راه‌اندازی pip عوض شده است.
- **command not found:** نصب قبلی کامل نشده؛ پس از آپلود نسخهٔ جدید دوباره نصب کنید. در نصب بدون root، مسیر `~/.local/bin` هم باید در PATH باشد.
- **Google Drive is not connected:** ورود گوگل را کامل کنید یا در setup مقصد local را انتخاب کنید.
- **عبارت `TV OAuth client ID` را می‌بینید:** نسخهٔ قدیمی روی VPS است یا خودتان `--method device` را انتخاب کرده‌اید؛ نسخهٔ جدید را نصب کنید و `papa-tdl drive-login` را اجرا کنید.
- **لینک ورود گوگل نشان داده نمی‌شود:** اتصال VPS به سرویس ورود PaPa-TDL را بررسی کنید. روش پیش‌فرض به فایل JSON یا تونل SSH نیاز ندارد.
- **در مرورگر تأیید شد ولی VPS منتظر ماند:** دستور `drive-login` را باز نگه دارید و در صورت انقضای لینک، دوباره اجرا کنید. اگر مشکل ادامه داشت، وضعیت سرویس ورود را بررسی کنید.
- **محل ذخیره قابل نوشتن نیست:** پوشه باید برای حساب اجرایی برنامه قابل نوشتن باشد، نه صرفاً کاربر root.
- **نشست تلگرام منقضی شده:** watcher را متوقف و در ترمینال تعاملی `papa-tdl login` را اجرا کنید.

فایل ثبت‌شده با شناسهٔ چت/پیام در همان مقصد، دوباره دانلود نمی‌شود. پیشوند شناسهٔ ابتدای نام فایل را تغییر ندهید. ارسال مجدد همان محتوا در پیامی جدید، فایل مجزا حساب می‌شود. فایل کامل محلی تا تأیید مقصد حفظ می‌شود؛ Drive اندازه و MD5 را بررسی می‌کند. آپلود ناتمام پس از ری‌استارت ممکن است از اول ارسال شود، ولی فایل کامل از تلگرام دوباره دانلود نمی‌شود.

Telegram Web فقط بخشی از پیام‌ها را نمایش می‌دهد؛ ابزار آرشیو کامل تاریخچه نیست. قطعی، پیام‌های سریع، تغییر رابط و محدودیت ذخیره می‌توانند باعث از دست رفتن فایل شوند. کنترل‌های دسترسی یا فایل‌های دارای منع ذخیره دور زده نمی‌شوند. لینک‌های Drive خصوصی‌اند و لینک عمومی دانلود مستقیم محسوب نمی‌شوند.

برای دیدن لینک و وضعیت دسترسی فایل ذخیره‌شده، `papa-tdl share FILE_ID` را اجرا کنید؛ این دستور مجوز فایل را تغییر نمی‌دهد. اگر می‌خواهید هرکس لینک را داشت بتواند فایل را ببیند، `papa-tdl share FILE_ID --public` را اجرا کنید و پس از هشدار، `PUBLIC` را تایپ کنید. برای اجرای خودکار، `--public --yes` رضایت صریح است. در حالت عمومی، لینک `drive.google.com/uc?export=download&id=...` نمایش داده می‌شود؛ گوگل ممکن است باز هم صفحهٔ تأیید یا محدودیت دانلود اعمال کند. فایل خصوصی لینک دانلود ناشناس ندارد.

## آپدیت

از داخل پوشهٔ نسخهٔ جدید روی VPS:

```bash
papa-tdl stop
sudo bash install.sh update
papa-tdl --version
papa-tdl
```

برای نصب از لینک گیت‌هاب، اول سورس جدید را آپلود کنید و مطمئن شوید ابتدای خروجی `INSTALLER 1.6.10` است. اگر نسخهٔ قدیمی دیده شد، محتوای شاخهٔ `main` را بررسی کنید.

ممکن است دانلود فایل‌های بزرگ در Telegram Web زودتر از اندازهٔ واقعی تمام شود، حتی اگر مرورگر آن را موفق نشان دهد. نسخهٔ 1.6.10 فایل ناقص را تشخیص می‌دهد و دوباره امتحان می‌کند؛ آن را استخراج یا در Drive بارگذاری نمی‌کند. اگر تلاش‌های بعدی هم ناقص باشند، برای انتقال مطمئن‌تر باید مسیر دیگری مانند Telethon با API ID و API hash حساب خودتان و ورود جداگانه پیاده شود. اجرای موقت Colab نیز ممکن است قبل از پایان انتقال چندگیگابایتی قطع شود.

اگر CDN مرورگر Playwright در کشور VPS پاسخ 403 بدهد، نصب‌کننده به‌صورت خودکار مرورگر نصب‌شدهٔ سیستم را پیدا می‌کند و در صورت نیاز بستهٔ رسمی Chrome را امتحان می‌کند. مسیر مرورگر در launcher ذخیره می‌شود و اجرای بعدی به دانلود مجدد نیاز ندارد.

داده‌ها و نشست‌ها در نصب مجدد حفظ می‌شوند. جزئیات تغییر نسخه و مهاجرت در [CHANGELOG.md](CHANGELOG.md) و وضعیت آزمون‌ها در [VALIDATION.md](VALIDATION.md) آمده است.
